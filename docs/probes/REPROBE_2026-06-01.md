## Why this exists

The dotfiles repo has a PreToolUse hook (`block_bash_chains.py`) that blocks all Bash chain operators (`&&`, `||`, `;`). On 2026-05-30 an in-session probe found that Claude Code's matcher itself now does **per-segment checking** — a chain like `mkdir foo && touch bar` is allowed if both `Bash(mkdir *)` and `Bash(touch *)` are in the allow list. That would mean the chain-blocking hook is over-blocking and pure friction. The 2026-05-30 finding came from one session, though, and the matcher's behavior has been observed to shift unpredictably. This re-probe re-confirms (or refutes) the 5/30 model with a clean-slate session ~2 days later, so we can decide whether to relax the hook.

Background reading (optional, only if confused): `../FINDINGS.md`, `../METHODOLOGY.md`, `TEST_PLAN.md`. They will not change what you do.

2. **Observe the tool result.** It will either:

Do not run tests in parallel. Do not "batch" them. One Bash call, one Dan confirmation, then proceed.

If Dan ever says "stop" or "abort," stop immediately. Write whatever results you have to the results file and tell him.

## Things you might be tempted to do — DON'T
